## 3. Подключение серверов и SSH
| # | Требование | Статус |
|---|---|---|
| 3.1 | Подключать сервера по SSH: IP / логин / пароль / порт | ✅ реально (этап 4): мастер «Добавить сервер» (название, теги, IP/порт/пользователь, пароль/свой ключ/ключ панели, заметка) с кнопкой «Проверить подключение» (факты + отпечаток до создания). **Пароль не сохраняется**: им один раз ставится ed25519-ключ панели в authorized_keys, дальше только ключ; свой ключ хранится шифрованным. Host key фиксируется (TOFU): смена → диалог сравнения отпечатков и «Доверять новому» за паролем, всё в Журнале |

| 3.2a | Управление окном терминала: **справа** кнопки свернуть / на весь экран / закрыть (мак-кружочки убраны — не кроссплатформенны). Открывается по кнопке в дефолтном малом размере | ✅ |
| 3.3 | SSH НЕ открыт по умолчанию — только по кнопке | ✅ |
| 3.4 | Окно PiP растягивается во все стороны | ✅ |
| 3.5 | Связь панель↔нода: гибрид — агент на ноде (Go) + SSH запасным путём | 📝 решение зафиксировано |
| 3.6 | Стек выбирает Claude (NestJS + Go-агент + React + Postgres + VictoriaMetrics + Redis + Caddy) | ✅ спек |
| 3.7 | **Порядок добавления сервера:** сначала ввод доступов SSH (IP, порт, логин, пароль/ключ) → подключение → **агент ставится по умолчанию** автоматически | ✅ демо · ✅ реально (этап 4) частично: SSH-подключение, факты, ключ, статус «агент не установлен», токен подключения агента; установка самого агента — этап 5 |
| 3.8 | Кнопка «**Обновить сервер**» (`apt update && apt upgrade -y`) с подтверждением | ✅ демо |
| 3.9 | Не только установка агента, но и **обновление агента**. Агент = полный доступ к серверу и его информации | ✅ демо / 📝 реально |
